# ちびっこ薬剤師 認定フォト

病院祭の小学生向け調剤体験で使う、スマートフォン用の記念撮影ページです。外部ライブラリやビルド工程のない静的サイトなので、そのままGitHub Pagesへ配置できます。

## できること

- 背面カメラを初期表示し、前面／背面を切り替え（親が子どもを撮る運用を想定）
- カメラが報告する実際の向きを使って前面映像の鏡表示を判定
- 3秒カウントダウン後に撮影
- ライブ映像を1Aの写真領域（細く縦長にし、上辺中央は平らで左右の上角だけが丸い形状）に配置し、9:16の完成画像を端末内のCanvasで合成
- JPEG（品質0.92）で保存し、JPEG出力が使えない場合だけPNGへ切り替え
- カメラが使えない場合は端末内の写真を選択して合成
- ページ非表示、撮影後、終了時にカメラの全トラックを停止
- 画面遷移時に遷移先の見出しへフォーカスし、読み上げ位置を通知

撮影画像はブラウザのメモリ上だけで扱います。このページが写真を自動送信・自動保存することはありません。撮影後に「写真を保存」を押した場合だけ、端末へ保存されます。アクセス解析、広告、Cookie、`localStorage`、`IndexedDB`は使用していません。

## ファイル構成

```text
index.html
styles.css
app.js
assets/
  frame-certificate-1a.png
  frame-lab-transparent.png（旧案の保管用）
.nojekyll
```

`assets/frame-certificate-1a.png` は選択済みの1A元画像（941×1672px）の複製です。画像そのものは加工せず、JavaScriptが中央の写真安全領域にだけ撮影画像を配置します。保存時は1080×1920pxの完成画像になります。

## 2026-09-19修正値

- カメラ初期値：`facingMode: "user"`（前面）から `facingMode: "environment"`（背面）へ変更。カメラ切替機能と、端末が背面カメラを報告しない場合のフォールバックは維持。
- 写真プレビュー領域：`left: 18.5185%; top: 14.5833%; width: 62.963%; height: 68.75%`。添付赤枠に合わせて細く上へ延ばし、下端も`83.3333%`まで延ばした。上辺中央は平らに残し、`border-radius: 18% 18% 0 0 / 7% 7% 0 0`で左右の上角だけを丸めた。
- 保存Canvas領域：`x: 200, y: 280, width: 680, height: 1320`。CSSプレビューと同じ位置・比率で、上端中央は直線、左右上角は楕円弧（横122px・縦92px）でクリップする。
- フレームPNGと外周装飾は変更せず、写真レイヤーだけを角丸形状にする。赤枠に合わせ、上部タイトル周辺の装飾と左右の乳鉢・チェックリストに写真が少し重なる前提とした。
- プレビューと保存Canvasは写真を背面、1Aフレームを前面にするレイヤー順へ変更。白い中央部は`multiply`合成で写真を見せ、フレームの文字・枠・乳鉢・クリップボード・葉・上下リボン等の装飾は前面に残す。

## GitHub Pagesで公開する手順

1. このフォルダの中身をGitHubリポジトリの公開対象へコピーします。
2. GitHubのリポジトリで **Settings → Pages** を開きます。
3. **Deploy from a branch** を選び、公開するブランチとフォルダを指定します。
4. 表示されたHTTPSのURLをiPhone SafariとAndroid Chromeで開き、実機テストを行います。
5. 動作確認後、そのURLをQRコードにします。

カメラ機能はHTTPSまたはlocalhostでのみ動作します。GitHub操作、Pages公開、QRコード作成はこの成果物には含まれていません。

## ローカル確認

ファイルを直接開くのではなく、ローカルHTTPサーバーで確認します。

```sh
python3 -m http.server 8000
```

その後、同じPCのブラウザで `http://localhost:8000/` を開きます。スマートフォンからPCのLAN内IPを開く場合はHTTPSではないため、カメラが許可されないことがあります。その場合も写真選択の動作確認はできます。

## 公開前に病院側で確認する項目

- 病院名、開催日、ロゴを掲載するか。掲載する場合は正式データと利用許可
- フレーム内の文言、文字の読みやすさ、1人・2人で顔や白衣が隠れないこと
- 病院の広報・個人情報・ロゴ利用ルールに合っていること
- iPhone SafariとAndroid Chromeで、許可、切替、撮影、保存、撮り直し、写真選択が動くこと
- QRコードアプリ内ブラウザで開いた場合のSafari／Chrome案内
- 開発者ツールで、撮影後に画像データのネットワーク送信がないこと

## 実機チェックリスト

- [ ] カメラ開始前にプライバシー案内が読める
- [ ] 前面カメラが鏡表示され、保存結果もプレビューと同じ向きになる
- [ ] 前面／背面切替を繰り返してもカメラが重複しない
- [ ] 単眼端末や切替できない環境では、現在のカメラを保ったまま案内が表示される
- [ ] 3秒カウントダウン後に撮影される
- [ ] 撮影後にカメラ利用中の表示が消える
- [ ] 保存ファイル名が `hospital-festival-photo-YYYYMMDD-HHMMSS.jpg` になる
- [ ] iPhoneで保存しづらい場合に長押し案内が出る
- [ ] カメラ権限拒否後も写真選択を利用できる
- [ ] 写真選択時も9:16中央トリミングとフレーム合成が行われる
- [ ] 再読み込みまたはタブ終了後、ページ内に撮影画像が残らない
- [ ] 画面遷移後、スクリーンリーダーのフォーカスが新しい画面の見出しへ移る

最終公開と会場運用の判断は、病院の担当者が行ってください。
